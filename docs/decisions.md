# 首版设计取舍

1. 使用 Python 3.11+ 标准库与 unittest，运行与测试不下载依赖；锁定可选构建 setuptools。避免在空项目中为了框架引入双后端。
2. 实验范围只包括本项目和自建无敏感数据夹具。公司业务代码、备份和凭据文件不作为实验输入；不自动安装软件、改变认证或开放端口。
3. WSL 无原生 Codex；Windows 有真实登录 CLI，因此先做 Windows 真实验证，同时在 WSL 跑离线测试，明确不把它当 WSL CLI 联调通过。未建立跨侧路径转换 runner。
4. 独立文件副本优于首版共享 Git worktree。源目录有无 Git 均可保存当前树，但本版本仅允许可信合成夹具；原有文件不 stash/reset。基线使用内容树哈希，不冒充 Git commit SHA。
5. Codex worker 只读输出 JSON 文件内容，由宿主在允许路径应用。首版不让模型选择任意命令或测试入口，也不支持通用补丁删除、重命名、二进制。reviewer 新会话读取实际证据，不接受 worker 的自报成功。
6. 每 run 串行，依赖先验收再运行后续任务。 accepted 事件顺序定义集成叠加顺序；DAG 的 JSON 排列不决定依赖关系。跨 run 同时运行需由用户外部限制，当前不声称全局资源调度。
7. lease 只判断是否失联，不能证明副作用未发生；恢复进入 needs_reconciliation，宁可人工核对也不盲目重放。没有 exactly-once 承诺。
8. 第一个 CLI 有真实调用，但账单/剩余额度未知；真实默认禁用，只提供显式合成夹具试运行。API、GUI、ACP 和第二 provider 保持未实现，不创建看似可用的占位适配器。
9. 宿主固定测试仍执行候选代码，普通环境白名单不能隔离磁盘和网络。完整 OS 隔离、权限越界 canary、跨产品 worker、生产加固是后续门槛，首版不能用来执行不可信代码。
